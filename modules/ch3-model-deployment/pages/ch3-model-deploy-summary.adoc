== Knowledge check

Test your understanding of the MaaS deployment architecture before moving on:

1. **Why must governed models be deployed using `LLMInferenceService` rather than the legacy deployment method?**
+
Models deployed for MaaS use the `LLMInferenceService` architecture, which is designed for large language models and integrates with the MaaS gateway for subscription-based quota enforcement. The legacy deployment method uses traditional KServe InferenceService resources with serving runtimes, which bypass the MaaS architecture entirely.

2. **What happens if a model is deployed and registered as a `MaaSModelRef`, but the user's group is not added to a `MaaSAuthPolicy`?**
+
The model will exist on the cluster, but no user will be able to route traffic to it. Without an authorization policy, users receive `403 Forbidden` errors even if they have a valid subscription.

3. **How does the Gateway API discovery endpoint (`/maas-api/v1/models`) handle model visibility when a developer authenticates with an `sk-oai-` API key?**
+
The API gateway intercepts the request and validates the provided API key. Because the key is permanently bound to a specific subscription, the endpoint dynamically filters the JSON response to show *only* the models allowed by that exact subscription.

== 🛠️ Day-2 Troubleshooting: Model Deployment & Catalog

As a Platform Engineer, you will field support tickets when models fail to deploy or users cannot connect. Use this guide to resolve common Day-2 issues:

**Issue: Model Pod stuck in `Pending` during an update**

* **The Hardware Trap:** You likely attempted a rolling update without spare GPU capacity. KServe keeps the old pod running (consuming the GPU) while trying to start the new pod.
* **The Fix:** If you lack spare GPUs, you must scale the old `llminferenceservice` down to 0 replicas to free the GPU, then scale it back up with the new configuration.

**Issue: The model does not appear in the Gen AI Studio catalog**

* **Verify Registration:** Check that the `MaaSModelRef` was created using `oc get maasmodelref -n <your-project-namespace>`. If the object does not exist, the operator did not register the model.
* **Use legacy deployment method:** If deployed via the UI, ensure the **Use legacy deployment method** checkbox was unchecked. Legacy deployments bypass the MaaS architecture entirely.

**Issue: User access errors (403 Forbidden)**

* **Missing Policies:** Verify that the user has both a subscription and an authorization policy. A subscription grants quota for specific models with token limits. An authorization policy is required to authorize groups to access model endpoints through the API gateway.
* **Selective Access Mismatch:** Confirm the user belongs to the OpenShift group explicitly listed in the AuthPolicy subjects.

**Issue: Authentication errors (401 Unauthorized)**

* **Invalid Tokens:** Ensure you are using a MaaS API key generated from the dashboard. OpenShift tokens are not valid for MaaS authentication.
* **Revoked/Expired Keys:** The API key might be expired or manually revoked. Generate a new MaaS API key.

**Issue: Model not found (404)**

* **Typo in URL:** Ensure the URL format is correct: `https://maas.<domain>/llm/<model-name>/v1/chat/completions`.
* **Incorrect Model Name:** Verify the exact model name using the `/v1/models` discovery endpoint.
