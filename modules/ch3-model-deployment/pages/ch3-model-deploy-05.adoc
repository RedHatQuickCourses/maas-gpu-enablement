= 3.4: Expanding the catalog with selective access

====
WARNING: This section is under development
====

ChocoTech's Marketing and R&D teams have returned with a new request. While Llama-3 is excellent for general reasoning, they need a dedicated, highly proficient coding assistant model to help generate Python scripts and automate their data pipelines.

As a platform engineer, you ran the hardware math (Section 3.1) and realized that deploying a massive model like Nemotron would require an A100 GPU cluster due to its VRAM footprint. Since those nodes are currently unavailable, you have pivoted to deploying `qwen3-8b`—a highly capable coding model that fits comfortably alongside your existing workloads on standard GPUs.

This exercise demonstrates how easily you can expand the model catalog as new business requirements emerge. More importantly, it demonstrates how to apply strict, selective access controls so that restricted models do not appear for unauthorized users.

[NOTE]
====
**Single-GPU Lab Clusters** +
If your lab environment only has a single GPU with limited VRAM (e.g., 24GB), you cannot run both Llama-3 and Qwen simultaneously. You can either scale down the previous Llama-3 deployment to 0 replicas before continuing, or simply read through this section to understand the governance mechanics without executing the YAML.


=== Deploy from the RHOAI console simplication step

To simplify the model deployment process through the OpenShift AI dashboard, let's create a URI data connection in the `chocotech-models` project. This configuration stores the exact OCI registry location of our ModelCar-packaged Qwen3-8b image and uses specific annotations so the UI automatically recognizes it.

[source,role="execute"]
----
cat <<EOF | oc apply -f -
apiVersion: v1
kind: Secret
metadata:
  name: qwen3-8b
  namespace: chocotech-models
  labels:
    opendatahub.io/dashboard: "true"
  annotations:
    opendatahub.io/connection-type-protocol: uri
    opendatahub.io/connection-type-ref: uri-v1
    openshift.io/display-name: "Qwen 3 8b ModelCar (v1.0)"
stringData:
  URI: oci://quay.io/redhat-ai-services/modelcar-catalog:qwen3-8b
type: Opaque
EOF
----

== Exercise 1: The deployment manifest

We will use the exact same `LLMInferenceService` structure as before to deploy the Qwen model via OCI Modelcar and automatically generate its `MaaSModelRef`. 

Review and apply the `qwen-deployment.yaml` manifest:

[source,role="execute"]
----
cat <<EOF | oc apply -f -
apiVersion: serving.kserve.io/v1alpha1
kind: LLMInferenceService
metadata:
  name: qwen3-8b
  namespace: chocotech-models
spec:
  # THE VAULT: Pointing to the Modelcar OCI image
  model:
    uri: oci://quay.io/redhat-ai-services/modelcar-catalog:qwen3-8b
  servingRuntime: "vllm-cuda-runtime"
  router:
    scheduler:
      template:
        containers:
          - name: main
            args:
              - '--pool-group'
              - 'inference.networking.x-k8s.io'
              - '--pool-name'
              - '{{ .ObjectMeta.Name }}-inference-pool'
  template:
    spec:
      containers:
        - name: main
          env:
            - name: VLLM_ADDITIONAL_ARGS
              value: "--max-model-len=4096 --gpu-memory-utilization=0.85"
  placement:
    accelerator:
      name: "nvidia.com/gpu"
      count: 1
---
apiVersion: maas.opendatahub.io/v1alpha1
kind: MaaSModelRef
metadata:
  name: qwen3-8b
  namespace: chocotech-models
spec:
  modelRef:
    kind: LLMInferenceService
    name: qwen3-8b
EOF
----

Check the status condition to verify the model is healthy and ready to serve traffic *(This may take several minutes to pull the OCI image)*:

[source,role="execute"]
----
oc wait --for=condition=ready llminferenceservice/qwen3-8b -n chocotech-models --timeout=600s
----

== Exercise 2: Post-Deployment Governance (Selective Access)

Currently, the Qwen model is successfully deployed and registered as a `MaaSModelRef`, but **no one has access to it**. 

We want to restrict this specialized coding model strictly to the **Silver (R&D)** and **Bronze (Marketing)** subscriptions. The Gold (Quality Control) team should not have access to it, as it is strictly designed for coding, not factory floor defect analysis.

In OpenShift AI 3.4, access is enforced entirely by `MaaSSubscription` and `MaaSAuthPolicy` resources. To grant access, we must append the new model reference to our existing governance manifests. 

1. **Append the model to the Silver and Bronze `MaaSSubscription` resources** to grant a token quota:
+
[source,role="execute"]
----
cat <<EOF | oc apply -f -
---
apiVersion: maas.opendatahub.io/v1alpha1
kind: MaaSSubscription
metadata:
  name: silver-plan
  namespace: models-as-a-service
spec:
  priority: 50
  owner:
    groups:
      - name: chocotech-rd
    users: []
  modelRefs:
    - name: llama-3-8b
      namespace: chocotech-models
      tokenRateLimits:
        - limit: 10000
          window: 1m
    # NEWLY ADDED MODEL QUOTA
    - name: qwen3-8b
      namespace: chocotech-models
      tokenRateLimits:
        - limit: 20000
          window: 1m
---
apiVersion: maas.opendatahub.io/v1alpha1
kind: MaaSSubscription
metadata:
  name: bronze-plan
  namespace: models-as-a-service
spec:
  priority: 10
  owner:
    groups:
      - name: chocotech-marketing
    users: []
  modelRefs:
    - name: llama-3-8b
      namespace: chocotech-models
      tokenRateLimits:
        - limit: 2000
          window: 1m
    # NEWLY ADDED MODEL QUOTA
    - name: qwen3-8b
      namespace: chocotech-models
      tokenRateLimits:
        - limit: 8000
          window: 1m
EOF
----

2. **Append the model to the Silver and Bronze `MaaSAuthPolicy` resources** to explicitly authorize traffic through the API Gateway:
+
[source,role="execute"]
----
cat <<EOF | oc apply -f -
---
apiVersion: maas.opendatahub.io/v1alpha1
kind: MaaSAuthPolicy
metadata:
  name: silver-access
  namespace: models-as-a-service
spec:
  modelRefs:
    - name: llama-3-8b
      namespace: chocotech-models
    # NEWLY ADDED MODEL ACCESS
    - name: qwen3-8b
      namespace: chocotech-models
  subjects:
    groups:
      - name: chocotech-rd
    users: []
---
apiVersion: maas.opendatahub.io/v1alpha1
kind: MaaSAuthPolicy
metadata:
  name: bronze-access
  namespace: models-as-a-service
spec:
  modelRefs:
    - name: llama-3-8b
      namespace: chocotech-models
    # NEWLY ADDED MODEL ACCESS
    - name: qwen3-8b
      namespace: chocotech-models
  subjects:
    groups:
      - name: chocotech-marketing
    users: []
EOF
----

The Gold Plan (Quality Control) remains completely untouched. Kuadrant will physically block any attempts from the Gold group to route traffic to the Qwen model.

== Exercise 3: Verify the multi-model catalog

**1. Generate a Test API Key** +
To accurately test selective access, you must generate an API key tied specifically to the Bronze Plan (Marketing).
* In the OpenShift AI dashboard, click **Gen AI studio** -> **API keys**.
* Click **Create API key**.
* Name it `marketing-qwen-test`.
* Select **Bronze** from the Subscription dropdown.
* Click **Create** and immediately copy the `sk-oai-...` key.

**2. The UI Payoff** +
Refresh the Gen AI Studio Models tab in the OpenShift AI dashboard.
* Since you are testing with Bronze/Silver access, you will now see both `llama-3-8b` and `qwen3-8b` listed with their respective subscription access controls. 
* If you switch to a user in the **Quality Control (Gold)** group, the Qwen model is entirely hidden from the catalog.

**3. API Discovery (The Developer View)** +
Retrieve your Gateway hostname and query the `/maas-api/v1/models` endpoint using the Bronze API Key you just generated:

[source,role="execute"]
----
# Ensure variables are set
export MAAS_API_KEY="sk-oai-..." # Paste your Bronze key here
export ROUTE_HOST=$(oc get route openshift-ai-inference -n openshift-ingress -o jsonpath='{.spec.host}')

curl -s -k -H "Authorization: Bearer $MAAS_API_KEY" \
  https://${ROUTE_HOST}/maas-api/v1/models | jq
----

*Expected output showing both models*:
[source,json]
----
{
  "object": "list",
  "data": [
    {
      "id": "llama-3-8b",
      "object": "model",
      "owned_by": "chocotech-models"
    },
    {
      "id": "qwen3-8b",
      "object": "model",
      "owned_by": "chocotech-models"
    }
  ]
}
----

*(Note: If you run this exact same API call using a Gold Plan API Key, the Gateway will dynamically filter the JSON response to only return `llama-3-8b`).*

ChocoTech now operates a fully governed, multi-model AI factory. Quality Control relies on the universally available Llama-3 for factory logic, while Marketing and R&D can utilize the specialized Qwen coder model without risking exposure to the Gold tier production environment.
