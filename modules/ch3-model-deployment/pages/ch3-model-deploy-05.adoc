= 3.4: Expanding the catalog via the UI

ChocoTech's Marketing and R&D teams need a dedicated coding assistant model (qwen3-4b). This exercise demonstrates how to expand the catalog using the OpenShift AI Dashboard UI, handle limited GPU capacity, and enforce selective access controls.

=== 1. Capacity Management: Scaling down Llama-3

If your lab environment only has a single GPU with limited VRAM (e.g., 24GB), you cannot run both Llama-3 and Qwen simultaneously. As a Platform Engineer, you must free up VRAM before deploying the new model. 

Rather than deleting the `llama-3-8b` deployment entirely, you will simply **stop** it using the OpenShift AI dashboard. This immediately releases the GPU back to the cluster while keeping your model configuration intact, allowing you to easily toggle between models later when testing different group and subscription combinations.

1. In the OpenShift AI dashboard, navigate to **AI HUB - Models** and select the `chocotech-models` project.
2. Click the **Deployments** tab.
3. Locate your `llama-3-8b` model in the list.
4. Click the action menu (the three vertical dots) next to the model, and select **Stop** (or toggle the status switch to the off position).
5. Wait a few moments for the status to update, confirming that the inference pod has spun down and the GPU has been successfully released.

== 2. Deploy Qwen3 via the Dashboard UI

While GitOps is powerful, OpenShift AI provides a seamless UI for model deployment. First, create the Data Connection secret so the UI knows where the Modelcar image lives:

[source,role="execute"]
----
cat <<EOF | oc apply -f -
apiVersion: v1
kind: Secret
metadata:
  name: qwen3-4b
  namespace: chocotech-models
  labels:
    opendatahub.io/dashboard: "true"
  annotations:
    opendatahub.io/connection-type-protocol: uri
    opendatahub.io/connection-type-ref: uri-v1
    openshift.io/display-name: "Qwen 3 4b ModelCar (v1.0)"
stringData:
  URI: oci://quay.io/redhat-ai-services/modelcar-catalog:qwen3-4b
type: Opaque
EOF
----

Now that the data connection is staged, follow these step-by-step instructions to configure the model runtime, hardware allocation, and MaaS governance properties.

1. In the OpenShift AI dashboard, navigate to your `chocotech-models` project and click the **Deployments** tab.
2. Click **Deploy model**.

=== Step 1: Model Details and Location

Instead of manually typing out the OCI registry URL, we will leverage the internal data connection you just created.

1. **Model location:** Select the down arrow button, then **Existing connection**.
2. **Name:** Select **Qwen 3 4b ModelCar (v1.0)** from the dropdown list.
3. **Model Type:** Select **Generative AI model (Example, LLM)**.
4. Click **Next**.

=== Step 2: Model Deployment Configuration

1. **Name:** Enter `qwen3-4b`.
2. **Hardware profile:** Select **nvidia-gpu** (or your designated gpu-profile).
3. **Deployment resource:** Select **manual**.
4. **Serving runtime:** From the dropdown menu, select **Distributed inference with llm-d**.
5. **Number of replicas:** Leave this set to `1`. (In a production environment, you would scale this for high availability and usage requirements).
6. Click **Next**.

=== Step 3: Advanced Settings & Governance

This step is critical for integrating the model into ChocoTech's financial and security framework.

 1. **Model Availability:** Check the box next to **Publish as MaaS**. +
Checking *Publish as MaaS* automatically instructs OpenShift AI to generate a `MaaSModelRef` resource under the hood. This links the newly created model endpoint directly to the MaaS gateway, enabling our Authorino security policies and Kuadrant token quotas to intercept traffic.

 2. **Configuration Parameters:** Select **Add custom runtime arguments**. This allows us to fine-tune the vLLM deployment. Add the following parameters:

[source,role="execute"]
----
--dtype=half 
--max-model-len=8192 
--gpu-memory-utilization=0.95
----

 3. **Routing Settings:** Leave the Rolling update selection and model route timeout selections set to their defaults.
 4. Review your configuration choices on the summary pane and click **Deploy model**.

== 3. The Identity Swap (Testing Selective Access)

Currently, the Qwen model is deployed, but no one has access to it. We want to restrict this model strictly to the **Silver (R&D)** and **Bronze (Marketing)** subscriptions.

1. **Append the model to the Silver and Bronze `MaaSSubscription` resources** to grant a token quota:
+
[source,role="execute"]
----
cat <<EOF | oc apply -f -
---
apiVersion: maas.opendatahub.io/v1alpha1
kind: MaaSSubscription
metadata:
  name: silver-plan
  namespace: models-as-a-service
spec:
  priority: 50
  owner:
    groups:
      - name: chocotech-rd
    users: []
  modelRefs:
    - name: llama-3-8b
      namespace: chocotech-models
      tokenRateLimits:
        - limit: 10000
          window: 1m
    # NEWLY ADDED MODEL QUOTA
    - name: qwen3-4b
      namespace: chocotech-models
      tokenRateLimits:
        - limit: 5000
          window: 1m
---
apiVersion: maas.opendatahub.io/v1alpha1
kind: MaaSSubscription
metadata:
  name: bronze-plan
  namespace: models-as-a-service
spec:
  priority: 10
  owner:
    groups:
      - name: chocotech-marketing
    users: []
  modelRefs:
    - name: llama-3-8b
      namespace: chocotech-models
      tokenRateLimits:
        - limit: 2000
          window: 1m
    # NEWLY ADDED MODEL QUOTA
    - name: qwen3-4b
      namespace: chocotech-models
      tokenRateLimits:
        - limit: 2000
          window: 1m
EOF
----

2. **Append the model to the Silver and Bronze `MaaSAuthPolicy` resources** to explicitly authorize traffic through the API Gateway:
+
[source,role="execute"]
----
cat <<EOF | oc apply -f -
---
apiVersion: maas.opendatahub.io/v1alpha1
kind: MaaSAuthPolicy
metadata:
  name: silver-access
  namespace: models-as-a-service
spec:
  modelRefs:
    - name: llama-3-8b
      namespace: chocotech-models
    # NEWLY ADDED MODEL ACCESS
    - name: qwen3-4b
      namespace: chocotech-models
  subjects:
    groups:
      - name: chocotech-rd
    users: []
---
apiVersion: maas.opendatahub.io/v1alpha1
kind: MaaSAuthPolicy
metadata:
  name: bronze-access
  namespace: models-as-a-service
spec:
  modelRefs:
    - name: llama-3-8b
      namespace: chocotech-models
    # NEWLY ADDED MODEL ACCESS
    - name: qwen3-4b
      namespace: chocotech-models
  subjects:
    groups:
      - name: chocotech-marketing
    users: []
EOF
----

The Gold Plan (Quality Control) remains completely untouched. Kuadrant will physically block any attempts from the Gold group to route traffic to the Qwen model.

**The Role Swap Challenge:**
You are currently an administrator in the Gold (Quality Control) group. Let's simulate a department transfer to prove our governance works. Remove yourself from the Gold group and add yourself to the Bronze (Marketing) group:

[source,role="execute"]
----
oc adm groups remove-users chocotech-quality-control $(oc whoami)
oc adm groups add-users chocotech-marketing $(oc whoami)
----

== 4. Revocation and Verification

Because API keys capture a snapshot of user group memberships from when the key was created, your old Gold API key is a security risk. To immediately revoke access after a group change, revoke the API keys for that user.

1. In the OpenShift AI dashboard, go to **Gen AI studio → API keys** and **Revoke** your previous key.

== Exercise 3: Verify the multi-model catalog

**1. Generate a Test API Key** +
To accurately test selective access, you must generate an API key tied specifically to the Bronze Plan (Marketing).
* In the OpenShift AI dashboard, click **Gen AI studio** -> **API keys**.
* Click **Create API key**.
* Name it `marketing-qwen-test`.
* Select **Bronze** from the Subscription dropdown.
* Click **Create** and immediately copy the `sk-oai-...` key.

**2. The UI Payoff** +
Refresh the Gen AI Studio Models tab in the OpenShift AI dashboard.
* Since you are testing with Bronze/Silver access, you will now see both `llama-3-8b` and `qwen3-4b` listed with their respective subscription access controls.
* If you switch to a user in the **Quality Control (Gold)** group, the Qwen model is entirely hidden from the catalog.

**3. API Discovery (The Developer View)** +
Retrieve your Gateway hostname and query the `/maas-api/v1/models` endpoint using the Bronze API Key you just generated:

[source,role="execute"]
----
# Ensure variables are set
export MAAS_API_KEY="sk-oai-..." # Paste your Bronze key here
export ROUTE_HOST=$(oc get route openshift-ai-inference -n openshift-ingress -o jsonpath='{.spec.host}')

curl -s -k -H "Authorization: Bearer $MAAS_API_KEY" \
  https://${ROUTE_HOST}/maas-api/v1/models | jq
----

*Expected output showing both models*:
[source,json]
----
{
  "object": "list",
  "data": [
    {
      "id": "llama-3-8b",
      "object": "model",
      "owned_by": "chocotech-models"
    },
    {
      "id": "qwen3-4b",
      "object": "model",
      "owned_by": "chocotech-models"
    }
  ]
}
----

*(Note: If you run this exact same API call using a Gold Plan API Key, the Gateway will dynamically filter the JSON response to only return `llama-3-8b`).*

ChocoTech now operates a fully governed, multi-model AI factory. Quality Control relies on the universally available Llama-3 for factory logic, while Marketing and R&D can utilize the specialized Qwen coder model without risking exposure to the Gold tier production environment.
