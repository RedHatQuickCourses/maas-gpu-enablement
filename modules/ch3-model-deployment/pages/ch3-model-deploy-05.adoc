= 3.4: Expanding the catalog via the UI

ChocoTech's Marketing and R&D teams need a dedicated coding assistant model (Qwen3-8b). This exercise demonstrates how to expand the catalog using the OpenShift AI Dashboard UI, handle limited GPU capacity, and enforce selective access controls.

== 1. Capacity Management: Scaling down Llama-3

If your lab environment only has a single GPU with limited VRAM (e.g., 24GB), you cannot run both Llama-3 and Qwen simultaneously. As a Platform Engineer, you must free up VRAM before deploying the new model.

Scale the Llama-3 deployment to 0 replicas:

[source,role="execute"]
----
oc scale llminferenceservice llama-3-8b -n chocotech-models --replicas=0
----

== 2. Deploy Qwen3 via the Dashboard UI

While GitOps is powerful, OpenShift AI provides a seamless UI for model deployment.

1. First, create the Data Connection secret so the UI knows where the Modelcar image lives:

[source,role="execute"]
----
cat <<EOF | oc apply -f -
apiVersion: v1
kind: Secret
metadata:
  name: qwen3-8b
  namespace: chocotech-models
  labels:
    opendatahub.io/dashboard: "true"
  annotations:
    opendatahub.io/connection-type-protocol: uri
    opendatahub.io/connection-type-ref: uri-v1
    openshift.io/display-name: "Qwen 3 8b ModelCar (v1.0)"
stringData:
  URI: oci://quay.io/redhat-ai-services/modelcar-catalog:qwen3-8b
type: Opaque
EOF
----

2. In the OpenShift AI dashboard, navigate to your `chocotech-models` project and click the **Deployments** tab.
3. Click **Deploy model**.
4. Configure the model:
  * Select **Generative AI model (Example, LLM)** as the model type.
  * Make sure that the **Use legacy deployment method** checkbox is **unchecked**. *(If checked, it bypasses MaaS entirely!)*
  * Select the `Distributed Inference with llm-d` deployment resource and nvidia-gpu hardware profile.
5. In the **Advanced settings** section, under Model availability, select **Publish as MaaS**.
6. Click **Deploy model**.

== 3. The Identity Swap (Testing Selective Access)

Currently, the Qwen model is deployed, but no one has access to it. We want to restrict this model strictly to the **Silver (R&D)** and **Bronze (Marketing)** subscriptions.


1. **Append the model to the Silver and Bronze `MaaSSubscription` resources** to grant a token quota:
+
[source,role="execute"]
----
cat <<EOF | oc apply -f -
---
apiVersion: maas.opendatahub.io/v1alpha1
kind: MaaSSubscription
metadata:
  name: silver-plan
  namespace: models-as-a-service
spec:
  priority: 50
  owner:
    groups:
      - name: chocotech-rd
    users: []
  modelRefs:
    - name: llama-3-8b
      namespace: chocotech-models
      tokenRateLimits:
        - limit: 10000
          window: 1m
    # NEWLY ADDED MODEL QUOTA
    - name: qwen3-8b
      namespace: chocotech-models
      tokenRateLimits:
        - limit: 20000
          window: 1m
---
apiVersion: maas.opendatahub.io/v1alpha1
kind: MaaSSubscription
metadata:
  name: bronze-plan
  namespace: models-as-a-service
spec:
  priority: 10
  owner:
    groups:
      - name: chocotech-marketing
    users: []
  modelRefs:
    - name: llama-3-8b
      namespace: chocotech-models
      tokenRateLimits:
        - limit: 2000
          window: 1m
    # NEWLY ADDED MODEL QUOTA
    - name: qwen3-8b
      namespace: chocotech-models
      tokenRateLimits:
        - limit: 8000
          window: 1m
EOF
----

2. **Append the model to the Silver and Bronze `MaaSAuthPolicy` resources** to explicitly authorize traffic through the API Gateway:
+
[source,role="execute"]
----
cat <<EOF | oc apply -f -
---
apiVersion: maas.opendatahub.io/v1alpha1
kind: MaaSAuthPolicy
metadata:
  name: silver-access
  namespace: models-as-a-service
spec:
  modelRefs:
    - name: llama-3-8b
      namespace: chocotech-models
    # NEWLY ADDED MODEL ACCESS
    - name: qwen3-8b
      namespace: chocotech-models
  subjects:
    groups:
      - name: chocotech-rd
    users: []
---
apiVersion: maas.opendatahub.io/v1alpha1
kind: MaaSAuthPolicy
metadata:
  name: bronze-access
  namespace: models-as-a-service
spec:
  modelRefs:
    - name: llama-3-8b
      namespace: chocotech-models
    # NEWLY ADDED MODEL ACCESS
    - name: qwen3-8b
      namespace: chocotech-models
  subjects:
    groups:
      - name: chocotech-marketing
    users: []
EOF
----

The Gold Plan (Quality Control) remains completely untouched. Kuadrant will physically block any attempts from the Gold group to route traffic to the Qwen model.

**The Role Swap Challenge:**
You are currently an administrator in the Gold (Quality Control) group. Let's simulate a department transfer to prove our governance works.

Remove yourself from the Gold group and add yourself to the Bronze (Marketing) group:

[source,role="execute"]
----
oc adm groups remove-users chocotech-quality-control $(oc whoami)
oc adm groups add-users chocotech-marketing $(oc whoami)
----

== 4. Revocation and Verification

Because API keys capture a snapshot of user group memberships from when the key was created, your old Gold API key is a security risk. To immediately revoke access after a group change, revoke the API keys for that user.

1. In the OpenShift AI dashboard, go to **Gen AI studio → API keys** and **Revoke** your previous key.
2. Create a new key and select the **Bronze Plan**.
3. Navigate to **Gen AI studio → AI asset endpoints**.
4. You will now see `qwen3-8b` listed. Because you are no longer in the Gold group, you are experiencing the exact, filtered catalog view that a Marketing developer sees!

== Exercise 3: Verify the multi-model catalog

**1. Generate a Test API Key** +
To accurately test selective access, you must generate an API key tied specifically to the Bronze Plan (Marketing).

* In the OpenShift AI dashboard, click **Gen AI studio** -> **API keys**.
* Click **Create API key**.
* Name it `marketing-qwen-test`.
* Select **Bronze** from the Subscription dropdown.
* Click **Create** and immediately copy the `sk-oai-...` key.

**2. The UI Payoff** +
Refresh the Gen AI Studio Models tab in the OpenShift AI dashboard.

* Since you are testing with Bronze/Silver access, you will now see both `llama-3-8b` and `qwen3-8b` listed with their respective subscription access controls. 
* If you switch to a user in the **Quality Control (Gold)** group, the Qwen model is entirely hidden from the catalog.

**3. API Discovery (The Developer View)** +
Retrieve your Gateway hostname and query the `/maas-api/v1/models` endpoint using the Bronze API Key you just generated:

[source,role="execute"]
----
# Ensure variables are set
export MAAS_API_KEY="sk-oai-..." # Paste your Bronze key here
export ROUTE_HOST=$(oc get route openshift-ai-inference -n openshift-ingress -o jsonpath='{.spec.host}')

curl -s -k -H "Authorization: Bearer $MAAS_API_KEY" \
  https://${ROUTE_HOST}/maas-api/v1/models | jq
----

*Expected output showing both models*:
[source,json]
----
{
  "object": "list",
  "data": [
    {
      "id": "llama-3-8b",
      "object": "model",
      "owned_by": "chocotech-models"
    },
    {
      "id": "qwen3-8b",
      "object": "model",
      "owned_by": "chocotech-models"
    }
  ]
}
----

*(Note: If you run this exact same API call using a Gold Plan API Key, the Gateway will dynamically filter the JSON response to only return `llama-3-8b`).*

ChocoTech now operates a fully governed, multi-model AI factory. Quality Control relies on the universally available Llama-3 for factory logic, while Marketing and R&D can utilize the specialized Qwen coder model without risking exposure to the Gold tier production environment.
