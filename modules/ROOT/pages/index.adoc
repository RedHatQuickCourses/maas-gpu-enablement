= Models as a Service: Breaking the GPU Silos on OpenShift AI 3.4

Welcome to this *Red Hat OpenShift AI 3.4 - Models as a Service* QuickCourse!

---

The CIO at ChocoTech Industries just called an emergency meeting. "We’ve invested over $500,000 in GPU infrastructure across four teams," she says, reviewing the quarterly report. "Yet our R&D team is waiting three weeks for capacity while Quality Control’s GPUs sit idle 60% of the time. This doesn’t make sense."

ChocoTech needs to align their AI Strategy to optimize for GPU utilization across business units, moving to a centralized, governed platform where all teams can access AI models efficiently.

== The MaaS Mandate

Designed for Platform Engineers and Developers, this course provides the steps to build a governed Models-as-a-Service (MaaS) ecosystem on OpenShift AI 3.4. We skip the trial-and-error of figuring out which operators and registries to install. 

Instead, you will learn how to immediately transform fragmented, isolated hardware into a fairly scheduled, multi-tenant shared service, empowering your business units to deploy agentic AI smoothly, securely, and at scale.

[NOTE]
====
**Experience Level**: Intermediate
====

== Prerequisites

To get the most out of this QuickCourse, you should come to the table with:

* Red Hat OpenShift administration experience (version 4.19.9 or later) 
* Basic Kubernetes operator management knowledge
* Familiarity with core GPU concepts and generic GPU enablement
* An understanding of API concepts and REST principles
* Basic command-line and Python experience
* Networking fundamentals (Routing traffic via Gateway API)

== What You'll Learn

In this hands-on QuickCourse, you will:

* **MaaS Strategy**: Understand how Models-as-a-Service solves complex GPU resource allocation and "Shadow AI" challenges.
* **Architect a Hub**: Design and implement a centralized model hub featuring governed, token-based consumption via Kuadrant and Authorino.
* **Configure and Deploy**: Set up MaaS using operators and deploy generative AI models leveraging the highly scalable `LLMInferenceService` architecture.
* **Integrate External Models**: Safely route traffic to external cloud providers (like OpenAI) using a two-tier authentication architecture.
* **Enforce Governance**: Implement strict token quotas and rate limits using `MaaSSubscription` and `MaaSAuthPolicy` custom resources.
* **Monitor and Report**: Enable telemetry, visualize API consumption, and export automated chargeback reports for financial accountability.
* **Integrate Seamlessly**: Connect AI models into downstream applications using OpenAI-compatible APIs with robust exponential backoff retry logic.
