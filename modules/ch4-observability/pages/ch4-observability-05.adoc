== Knowledge check

Test your understanding of MaaS observability and integration before concluding the course:

1. **Why is it critical for client applications to read the `Retry-After` header when they receive a `429 Too Many Requests` error?**
+
If applications ignore the header and aggressively retry, they waste network resources and continue to hit the rate limit. Reading the header allows the application to pause execution (exponential backoff) and resume exactly when the token bucket has refilled.

2. **Why is the `captureUser` telemetry flag set to `false` by default in the Tenant custom resource?**
+
Enabling user-level tracking on a cluster with hundreds or thousands of users exponentially increases metric cardinality. This can severely bloat the Prometheus database and impact cluster monitoring performance. (We used `app_id` to track API keys instead!)

3. **What are the three pillars of AI Observability?**
+
A production-grade AI platform must monitor *User Experience* (Time to First Token/Latency), *Hardware Efficiency* (GPU Utilization and VRAM), and *Model Health* (Queue Depth and HTTP Server errors).

.🛠️ Troubleshooting: Observability & Grafana (Click to expand)
[%collapsible]
====
If you encountered any issues generating traffic or viewing metrics, check the following common resolutions:

**Issue: Grafana doesn't have the OpenShift-Prometheus data source**

* **The Cause:** The Grafana Operator uses label selectors to bind datasources. If your Grafana instance was missing the `dashboards: "grafana"` label, the operator ignored it.
* **The Fix:** Apply the label (`oc label grafana chocotech-grafana dashboards=grafana -n chocotech-models`), then delete and recreate the `GrafanaDatasource` resource to wake the operator up.

**Issue: Cannot reach the Grafana URL (Route Not Found)**

* **The Cause:** Depending on the OpenShift ingress configuration, the v5 Grafana Operator sometimes fails to generate a Route automatically. 
* **The Fix:** Manually expose the backend service using `oc create route edge chocotech-grafana --service=chocotech-grafana-service -n chocotech-models`.

**Issue: Grafana Query Editor only shows dropdowns**

* **The Cause:** Grafana defaults to "Builder" mode.
* **The Fix:** Look at the far right of the query row and click the **Code** toggle button to switch to text mode, allowing you to paste raw PromQL queries.

**Issue: No metrics are appearing in Grafana or OpenShift Console**

* **Prometheus is not a time machine:** Metrics only appear *after* the `PodMonitor` and Tenant telemetry are enabled. If you ran the Python script before patching Kuadrant/Tenant, you must delete the old Kubernetes Job and redeploy it to generate fresh traffic!
