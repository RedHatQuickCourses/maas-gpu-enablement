== Knowledge check

Test your understanding of MaaS observability and integration before concluding the course:

1. **Why is it critical for client applications to read the `Retry-After` header when they receive a `429 Too Many Requests` error?**
+
If applications ignore the header and aggressively retry, they waste network resources and continue to hit the rate limit. Reading the header allows the application to pause execution (exponential backoff) and resume exactly when the token bucket has refilled.

2. **Why is the `captureUser` telemetry flag set to `false` by default in the Tenant custom resource?**
+
Enabling user-level tracking on a cluster with hundreds or thousands of users exponentially increases metric cardinality. This can severely bloat the Prometheus database and impact cluster monitoring performance.

3. **What is the difference between Kuadrant observability and MaaS Tenant telemetry?**
+
Kuadrant observability (via Limitador) tracks *enforcement*—specifically, how many requests were rejected due to rate limits. MaaS Tenant telemetry tracks *consumption*—specifically, how many input and output tokens were processed by the models.

.🛠️ Troubleshooting: Observability & Integration (Click to expand)
[%collapsible]
====
If you encountered any issues generating traffic or viewing metrics, check the following common resolutions:

**Issue: No metrics are appearing in the Usage dashboard**

* **Check Telemetry Flags:** Ensure both the Kuadrant `observability.enable: true` and the Tenant `telemetry.enabled: true` patches were successfully applied.
* **Generate Traffic:** Metrics only appear after requests are made. Ensure your Python script successfully ran and generated traffic.
* **Verify User Workload Monitoring:** MaaS observability requires OpenShift's User Workload Monitoring to be enabled on the cluster. Without it, the MaaS deployment will degrade.

**Issue: The CSV export contains missing "User" data**

* **Expected Behavior:** Because we explicitly set `captureUser: false` in the Tenant patch to protect database performance, the exported CSV will not break down token consumption by individual users, but rather by the aggregated Subscription.

**Issue: The Python script crashes with an SSL/TLS error**

* **Check Warnings:** In a lab environment with self-signed certificates, ensure you included `verify=False` in your Python `requests.post()` call and suppressed warnings using `export PYTHONWARNINGS="ignore:Unverified HTTPS request"`.

**Issue: The Usage tab is missing from the Dashboard**

* **Check Dashboard Config:** Verify that `spec.dashboardConfig.observabilityDashboard` is set to `true` in the `OdhDashboardConfig` custom resource.
