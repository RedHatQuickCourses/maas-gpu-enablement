= 4.3: OpenShift Metrics and Chargeback

The simulated developer traffic has concluded, and the telemetry pipeline is actively scraping Kuadrant's rate-limiting logs and the MaaS Gateway's token counters. 

It is time to answer the final business request from ChocoTech's Finance team: *"How much of the monthly cloud budget did the Marketing department consume this week?"*

As a platform engineer, you will use OpenShift's native observability tools to query the underlying Prometheus metrics. This gives you the exact raw data needed to generate showback reports for the business.

== Exercise 1: Accessing OpenShift Metrics

Let's navigate to the native OpenShift metrics console to visualize the chaos our load-generator script created.

1. Switch from the OpenShift AI dashboard to the main **OpenShift Web Console**.
2. Ensure you are logged in as a cluster administrator.
3. In the left-hand navigation menu, click **Observe** -> **Metrics**.
4. You will use the PromQL (Prometheus Query Language) interface to extract the MaaS billing data.

== Exercise 2: Querying the Telemetry

You will run three specific queries to extract the business value from the platform. Enter each query into the Expression box and click **Run queries**.

**1. Querying Total Tokens (The Billing Metric)** +
Run the following query:
[source,promql]
----
authorized_hits
----
* **The Business Value:** This metric represents the absolute total number of tokens (input prompts + model responses) successfully consumed. Because rate-limited (HTTP 429) requests are physically blocked at the gateway, they consume zero tokens. This is the exact hard data Finance uses to bill the department.
* **The Labels:** Notice the data is labeled by `subscription` (e.g., Bronze, Silver) and `model`, allowing you to see exactly how much the Marketing team consumed on `qwen3-4b`.

**2. Querying Total Requests** +
Run the following query:
[source,promql]
----
authorized_calls
----
* **The Business Value:** This tracks the total number of successful API requests made to the models. 

**3. Querying Rate Limit Violations (The Chaos Metric)** +
Run the following query:
[source,promql]
----
limited_calls
----
* **The Business Value:** This metric validates your governance policies. It reflects the total number of requests rejected due to rate limiting (HTTP 429 responses). This directly correlates to the moments when the Python script breached the Bronze token quota and Kuadrant intervened.

== Exercise 3: Exporting the Chargeback Report

Finance requires structured data to process inter-departmental billing. OpenShift allows you to export these PromQL results directly to a CSV file.

1. Ensure your Expression box is querying the primary billing metric: `authorized_hits`.
2. In the Metrics UI, look for the **Export** or **Download CSV** icon (typically located near the top right of the query results table).
3. Click to download the data to your local system.

You can now email this file to the Finance team, providing them with the exact mathematical proof they need to attribute GPU costs to the Marketing department.
