2.6: Summary & troubleshooting

You have successfully transformed ChocoTech’s OpenShift AI platform from a raw, ungoverned infrastructure into a highly secure, multi-tenant enterprise AI factory. If ChocoTech had opted for a generic public API, they would currently have zero internal cost control and no way to prioritize mission-critical workloads over experimental scripts. By building these policies directly into the OpenShift network edge, you have secured the company’s ROI and established absolute Quality of Service (QoS).

What you accomplished

  • Organizational Identity: Created OpenShift groups to represent specific business units (chocotech-quality-control, chocotech-rd, chocotech-marketing), ensuring audit trails are mapped to departments, not just individuals.

  • Programmatic Security: You established a workflow where developers can self-serve secure, revocable sk-oai- API keys directly from the Gen AI Studio dashboard.

  • Subscription Definition: Deployed MaaSSubscription custom resources into the models-as-a-service namespace, instructing the platform on exactly how to categorize ChocoTech’s business units and enforce token quotas.

  • Edge-Level Governance: Deployed MaaSAuthPolicy resources to physically authorize Gateway access for your groups. You successfully decoupled the inference request from the underlying GPU, ensuring that traffic limits are enforced mathematically at the network edge.

Knowledge check

Test your understanding of the subscription governance architecture before moving on:

  1. Why is there no risk of "ungoverned access" if you deploy a model before creating its MaaS Subscription?

    OpenShift AI operates on a default-deny security posture at the network edge. When you deploy a model and check "Publish as MaaS", the platform creates a MaaSModelRef object, but it does not grant any access. Users are strictly required to have both a subscription (to define token quotas) and an authorization policy (to grant API gateway access). Until an administrator explicitly links the model to a group via these policies, all incoming requests will be automatically rejected by Authorino with a 403 Forbidden error.

  2. What happens if a Bronze subscription user (Marketing) tries to exceed 2,000 tokens per minute?

    Kuadrant’s Limitador component, operating at the network edge, tracks the token consumption per subscription. It immediately rejects any requests exceeding the limit with an HTTP 429 Too Many Requests status code, preventing the request from ever reaching the KServe model pod. The user’s application must wait until the next minute window resets.

  3. How does the system know which subscription limits to apply to a programmatic user’s request?

    The API gateway intercepts the request and validates the provided API key (sk-oai-…​). Because the key was permanently bound to the user’s OpenShift group membership and highest priority subscription at the time it was created, the gateway immediately applies the correct token limits.

🛠️ Day-2 Troubleshooting: Governance & Authentication

As you integrate applications, you will inevitably run into authorization errors. Use this cheat sheet to diagnose Gateway rejections:

Issue: Request returns 401 Unauthorized

  • Check API Key Prefix: Ensure you’re using the Authorization: Bearer <key> header format with the full API key including the sk-oai- prefix. OpenShift tokens are not valid for MaaS authentication.

  • Check Key Revocation: The API key might be expired or manually revoked. Generate a new MaaS API key from the dashboard.

Issue: Request returns 403 Forbidden

  • The Missing AuthPolicy Trap: A subscription grants quota, but an AuthPolicy grants access. Without an authorization policy, users receive 403 Forbidden errors even if they have a valid subscription.

  • Verify AuthPolicy Configuration: Ask your administrator to verify that an authorization policy exists for your groups to access the model through the API gateway. Ensure your OpenShift group is explicitly listed in the subjects array.

Issue: Request returns 429 Too Many Requests

  • Token Limits Exhausted: This means Kuadrant’s Limitador component blocked the request because your subscription token limits are exhausted.

  • Implement Backoff: Ensure your application’s retry logic is respecting the Retry-After header value provided in the 429 response.
