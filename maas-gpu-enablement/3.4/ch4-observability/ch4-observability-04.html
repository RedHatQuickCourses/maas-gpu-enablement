4.4: Advanced Telemetry & The "God View" Dashboard

This section is under development

You have successfully delivered the chargeback report to the Finance team using the native OpenShift metrics console.

A note on the OpenShift AI UI: Depending on your specific build version or RBAC permissions, you may occasionally see an "Observe & monitor" tab in the OpenShift AI dashboard. However, because this feature is often hidden behind feature flags in early releases, we will not rely on it. Instead, we will do what true Platform Engineers do: build our own centralized "God View" using Grafana.

Tokens tell you how much was generated, but latency tells you how fast it felt to the user. Hardware metrics tell you if the physical cluster is burning out. To get a complete 360-degree view of your Enterprise AI Factory, we need to bring all these metrics into one place.

The Three Pillars of AI Observability

Beyond token counting, a production-grade AI platform requires monitoring across three specific domains:

  • User Experience (Latency): Large Language Models stream their text.

    • Time To First Token (TTFT) measures the "loading time" before the first word appears.

    • Inter-Token Latency (ITL) measures the "typing speed" of the subsequent words. If these spike, applications feel broken.

  • Hardware Efficiency (GPU): Monitoring raw GPU Utilization and VRAM Usage tells you if your models are efficiently batched or if you need to buy more physical hardware.

  • Model Health (Queues): Tracking Queue Depth reveals if user requests are piling up waiting for GPU compute cycles.

Exercise 1: Deploying the Grafana Instance

The Grafana Operator is already installed on your cluster. Let’s deploy a physical Grafana instance into the chocotech-models namespace.

Notice the labels section! The operator uses this label to automatically bind our Prometheus data source to this specific Grafana instance later.

cat <<EOF | oc apply -f -
apiVersion: grafana.integreatly.org/v1beta1
kind: Grafana
metadata:
  name: chocotech-grafana
  namespace: chocotech-models
  labels:
    dashboards: "grafana"
spec:
  config:
    auth.anonymous:
      enabled: "true"
      org_role: "Admin"
EOF

Note: We are enabling anonymous admin access strictly for this lab environment so you do not have to fight with login credentials during the exercise.

Because operators can sometimes behave differently depending on the cluster’s ingress configuration, we will explicitly command OpenShift to expose the Grafana service over HTTPS:

oc create route edge chocotech-grafana --service=chocotech-grafana-service -n chocotech-models

Exercise 2: Connecting the Prometheus Datasource

Grafana needs permission to read the data from OpenShift’s central Prometheus database (Thanos Querier). First, we grant the Grafana service account cluster-monitoring permissions.

oc adm policy add-cluster-role-to-user cluster-monitoring-view -z chocotech-grafana-sa -n chocotech-models

Next, we extract a security token and dynamically create the GrafanaDatasource custom resource so Grafana knows exactly where to pull the metrics from.

export SA_TOKEN=$(oc create token chocotech-grafana-sa -n chocotech-models --duration=24h)

cat <<EOF | oc apply -f -
apiVersion: grafana.integreatly.org/v1beta1
kind: GrafanaDatasource
metadata:
  name: openshift-prometheus
  namespace: chocotech-models
spec:
  instanceSelector:
    matchLabels:
      dashboards: "grafana"
  datasource:
    name: OpenShift-Prometheus
    type: prometheus
    access: proxy
    url: https://thanos-querier.openshift-monitoring.svc.cluster.local:9091
    isDefault: true
    jsonData:
      tlsSkipVerify: true
      timeInterval: "5s"
      httpHeaderName1: "Authorization"
    secureJsonData:
      httpHeaderValue1: "Bearer ${SA_TOKEN}"
EOF

Exercise 3: Accessing Grafana and Building Panels

Your Grafana instance is now live and wired into the cluster’s telemetry stream! Retrieve your secure Grafana URL:

oc get route chocotech-grafana -n chocotech-models -o jsonpath='{"https://"}{.spec.host}{"\n"}'

Open that URL in a new browser tab.

Step 1: Import the NVIDIA Hardware Dashboard

NVIDIA provides an excellent pre-built dashboard for DCGM metrics. 1. In Grafana, click the + (Create) icon in the left menu and select Import. 2. Type 12239 into the "Import via grafana.com" field and click Load. 3. Select OpenShift-Prometheus from the datasource dropdown at the bottom and click Import. 4. You now have a real-time view of your GPU Utilization, Temperature, and VRAM capacity!

Step 2: Build the Custom MaaS Dashboard

Now, let’s create a custom dashboard for your finance and governance metrics.

  1. Click the + icon and select New Dashboard.

  2. Click Add visualization and select OpenShift-Prometheus as your data source.

  3. IMPORTANT: By default, Grafana opens the query editor in "Builder" mode (using dropdown menus). To paste the exact PromQL queries below, look at the right side of the query row and click the Code button to switch to text mode!

Build the following panels:

Panel 1: Total Tokens Consumed (Finance)
Set the visualization type to Stat or Gauge.

sum(authorized_hits{model="qwen3-8b"})

Panel 2: Tokens Consumed by User (Chargeback)
Set the visualization type to Bar chart or Pie chart. This query groups the token consumption by the specific API Key ID (app_id)!

sum(authorized_hits{model="qwen3-8b"}) by (app_id)

Panel 3: Rate Limit Rejections (Governance)
Set the visualization type to Time series.

sum(rate(limited_calls[5m]))

Panel 4: Time To First Token (Latency/SRE)
Set the visualization type to Time series. This shows the 95th percentile loading time for your models.

histogram_quantile(0.95, sum(rate(vllm:time_to_first_token_seconds_bucket[5m])) by (le, model_name))

Save your dashboard. You now have a unified "God View" of your entire AI infrastructure!
