Exercise 3: Run the Load Generator (Kubernetes Job)

Instead of running a Python script on our local machine, we are going to run this exactly how the Marketing department would: as a containerized Kubernetes Job running inside the cluster.

We are going to deploy a self-contained container that automatically writes and executes a Python load-generation script. This script continuously sends prompts to the Gateway and uses exponential backoff to handle rate limits.

1. Secure the API Key First, save the Marketing API key you just generated into a Kubernetes Secret so our container can mount it securely:

export MAAS_API_KEY="<your-copied-bronze-api-key>"

oc create secret generic marketing-api-key \
  --from-literal=key=$MAAS_API_KEY \
  -n chocotech-models

2. Deploy the Batch Job Next, retrieve the Gateway URL and deploy the Kubernetes Job. This will spin up a lightweight Python container, dynamically write our batch script, and execute it against the MaaS API.

export GATEWAY_HOST=$(oc get gateway maas-default-gateway -n openshift-ingress -o jsonpath='{.status.addresses[0].value}')

cat <<EOF | oc apply -f -
apiVersion: batch/v1
kind: Job
metadata:
  name: marketing-chaos-job
  namespace: chocotech-models
spec:
  backoffLimit: 0
  template:
    spec:
      containers:
      - name: chaos-generator
        image: registry.access.redhat.com/ubi9/python-311
        command: ["/bin/bash", "-c"]
        args:
          - |
            pip install --quiet requests urllib3

            # Write the Python script dynamically
            cat << 'PYEOF' > marketing-batch-job.py
            import os
            import time
            import requests
            import urllib3

            urllib3.disable_warnings(urllib3.exceptions.InsecureRequestWarning)

            api_key = os.getenv("MAAS_API_KEY")
            base_url = os.getenv("MAAS_URL")
            url = f"{base_url}/v1/chat/completions"

            headers = {
                "Authorization": f"Bearer {api_key}",
                "Content-Type": "application/json"
            }

            data = {
                "model": "meta-llama/Meta-Llama-3-8B-Instruct",
                "messages": [{"role": "user", "content": "Write a detailed 500 word essay on the history of chocolate manufacturing."}],
                "max_tokens": 600
            }

            print(f"Starting batch job against {url}...\n")

            for i in range(1, 20):
                print(f"Request {i}...", end=" ")
                response = requests.post(url, headers=headers, json=data, verify=False)

                if response.status_code == 200:
                    print("✅ Success! Consumed tokens.")
                elif response.status_code == 429:
                    retry_after = int(response.headers.get("Retry-After", 10))
                    print(f"🛑 429 Rate Limit Hit! Sleeping for {retry_after} seconds...")
                    time.sleep(retry_after)
                else:
                    print(f"❌ Error: {response.status_code} - {response.text}")
                    time.sleep(2)
            PYEOF

            echo "Executing batch script against $MAAS_URL..."
            python marketing-batch-job.py
        env:
        - name: MAAS_API_KEY
          valueFrom:
            secretKeyRef:
              name: marketing-api-key
              key: key
        - name: MAAS_URL
          value: "https://${GATEWAY_HOST}"
      restartPolicy: Never
EOF

3. Watch the Chaos! The job is now running in the background. Let’s tail the logs of the container to watch it interact with the Kuadrant rate limiter in real time:

oc logs -f job/marketing-chaos-job -n chocotech-models

Expected Behavior: Watch the terminal output closely.

  1. The first few requests will succeed, returning ✅ Success! Consumed tokens.

  2. Because the Bronze Plan has a strict token limit, the script will rapidly consume its quota.

  3. Suddenly, you will see 🛑 429 Rate Limit Hit! Sleeping for X seconds…​. This is Kuadrant physically protecting the cluster GPUs from the Marketing team’s aggressive batch job.

  4. The Python script reads the Retry-After header, sleeps for the required time, and successfully resumes processing once the Kuadrant token bucket refills.

(Press Ctrl+C to exit the log tail when you are satisfied).
