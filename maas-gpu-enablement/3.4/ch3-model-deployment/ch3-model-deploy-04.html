3.3: Verifying the MaaS catalog and gateway publication

This section is under development

If ChocoTech had deployed this model using standard open-source tools, the Platform Engineering team’s job would not be finished. They would still need to manually write documentation, securely email the endpoint URL to the developers, and coordinate static API keys.

With Models-as-a-Service, OpenShift AI handles all of this automatically through a self-service catalog.

Exercise 1: Verify the backend MaaS registration

In the previous section, we explicitly deployed a MaaSModelRef custom resource alongside our model. This resource references inference servers served through OpenShift AI and registers them with the MaaS Gateway.

Verify the model was successfully registered with the MaaS API:

oc get maasmodelref -n chocotech-models

Expected output:

NAME             MODELREF_KIND         MODELREF_NAME    READY   AGE
llama-3-8b       LLMInferenceService   llama-3-8b       True    5m

By itself, this MaaSModelRef does not grant anyone access. However, because you "pre-wired" your governance in Module 2 by explicitly adding llama-3-8b to your Gold, Silver, and Bronze Subscriptions and AuthPolicies, the model is now instantly accessible and fully governed by Kuadrant rate limits.

Exercise 2: The Developer Payoff (Generating API Keys)

Let’s switch hats. You are now a developer on the Marketing team logging in to find a model for your sentiment analysis application. You do not need to know anything about vLLM or OpenShift routes; you simply use the self-service catalog.

Prerequisite: Ensure you are logged into the OpenShift AI dashboard as a user who belongs to the OpenShift group mapped to the Bronze or Silver subscription (e.g., chocotech-marketing).

  1. Navigate to Gen AI studio → AI asset endpoints in the left-hand menu.

  2. Click on the Models tab.

You should immediately see the llama-3-8b model populated in the catalog grid. Clicking the View button under the Endpoints column reveals a dialog with a Model as a Service badge.

This dialog provides critical connection details:

  • The external API endpoint URL: The exact gateway routing URL developers need.

  • Subscription Selector: A dropdown for choosing which subscription’s token quota to draw from.

  • Temporary API Key: A button to generate a 1-hour temporary API key for quick testing.

Creating a Persistent API Key

For a real application, developers need a persistent API key rather than a 1-hour temporary key.

  1. In the OpenShift AI dashboard, click Gen AI studio → API keys.

  2. Click Create API key.

  3. Give the key a descriptive name (e.g., marketing-sentiment-app).

  4. From the Subscription dropdown, select the subscription that determines your token limits.

  5. Leave the Expiration at the default (30 days) and click Create.

Copy the generated key immediately (it starts with sk-oai-). The plaintext key is displayed only during creation and cannot be retrieved later.

API Key Snapshots: API keys capture the user’s group memberships at the exact time of creation. If a user is removed from an OpenShift group later, their existing API keys retain the original group associations and continue to work until they are explicitly revoked or expired.

Exercise 3: Test API discovery (Listing Models)

The MaaS Gateway is fully compliant with the OpenAI API specification. However, in OpenShift AI 3.4, API discovery is highly secure and strictly scoped. When an application queries the /maas-api/v1/models endpoint using a generated sk-oai- API key, the Gateway automatically filters the response to show only the models allowed by the subscription bound to that specific key.

Retrieve your Gateway URL and query the models list using the persistent API key you just generated:

# Ensure your variables are set
export MAAS_API_KEY="sk-oai-..." # Paste your actual key here
export ROUTE_HOST=$(oc get route openshift-ai-inference -n openshift-ingress -o jsonpath='{.spec.host}')

# Query the MaaS API for available models
curl -H "Authorization: Bearer $MAAS_API_KEY" \
  https://${ROUTE_HOST}/maas-api/v1/models | jq

You should receive a JSON response listing llama-3-8b, confirming that Kuadrant validated your API key, verified your subscription, and successfully authorized the request.

Important Note for Administrators: Telemetry Limitations

Because Kuadrant tracks every token that passes through the gateway, OpenShift AI provides an out-of-the-box observability dashboard for administrators. As you prepare to build chargeback reports for ChocoTech’s Finance team, you must be aware of two specific telemetry configurations:

  1. User Tracking is Disabled by Default: To reduce metric cardinality and protect privacy, the captureUser setting in the telemetry configuration is set to false by default.

  2. Model Label Limitations: When inspecting the underlying Prometheus metrics, you will find that the model label (which identifies whether traffic hit llama-3 or another model) only appears on the authorized_hits metric.

Due to limitations in the Kuadrant wasm-shim, the model label does not appear on the authorized_calls (total API requests) or limited_calls (rate-limited HTTP 429 rejections) metrics. Keep this in mind when troubleshooting or building custom Grafana dashboards for specific models.
