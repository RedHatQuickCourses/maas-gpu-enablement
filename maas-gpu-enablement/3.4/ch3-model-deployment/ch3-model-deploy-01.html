Module 3: Deploying models to the MaaS catalog

With the governance fences securely built at the network edge, it is time to bring ChocoTech’s AI Model Catalog online. The R&D and Quality Control teams have submitted an urgent request: "We need access to Llama-3-8b for recipe optimization and defect analysis." For the second LLM you will substitute qwen3-4b for Nvidia Nemotron, and make qwen3-4b model only available to the Marketing and R&D teams.

Your task is to deploy these generative AI models onto your GPU nodes, ensure they integrate with the MaaS Gateway you built in Module 1, and properly link them to the Gold, Silver, and Bronze subscriptions an authorizations you defined in Module 2.

For the lab environments with a single GPU, we’ll swap models by stopping llama-3-8b model.

Learning objectives

By the end of this module, you will be able to:

  • Provision model serving runtimes using distributed inference with llm-d.

  • Understand how selecting the "Publish as MaaS" function automatically generates MaaSModelRef custom resources to register models with the gateway.

  • Execute post-deployment governance steps to generate API Keys for deployed models linking to the MaaSSubscription and MaaSAuthPolicy resources.

The deployment strategy

Deploying a model and making it accessible through MaaS is a strict, multi-step process. In this module, you will execute the following strategy to ensure complete governance:

Phase Action

1. Hardware & Runtime Sizing

Analyze the hardware requirements for your target models and select the appropriate serving runtime (llm-d).

2. The Deployment

Provision the model using the LLMInferenceService architecture. You will explicitly ensure the model does not bypass the MaaS gateway.

3. Registration (MaaSModelRef)

Use the "Publish as MaaS" feature to automatically generate a MaaSModelRef custom resource, notifying the MaaS platform that the model is ready for governance.

4. Post-Deployment Governance

A model published to MaaS is not immediately accessible. You will manually generate an API Key for access, officially closing the governance loop.

By the end of this module, ChocoTech’s business units will finally have self-service, heavily governed access to state-of-the-art AI models.
