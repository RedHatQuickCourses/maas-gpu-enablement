3.2: Deploying the Governed Model via the OpenShift AI UI

This section is under development

While advanced platform engineers often manage workloads via GitOps pipelines, OpenShift AI provides a cloud-native, wizard-driven user interface specifically designed for deploying models into a Models-as-a-Service (MaaS) fabric. Using the UI allows us to quickly configure inference runtimes, allocate dedicated GPU resources, and directly publish the model to the centralized MaaS gateway without writing complex Kubernetes Custom Resources by hand.

In this exercise, you will step into the role of the AI Platform Administrator and use the OpenShift AI model deployment wizard to deploy our target model (llama-3-8b) into the chocotech-models project.

Exercise 1: Create the ModelCar Data Connection

To simplify the model deployment process through the OpenShift AI dashboard, we will first create a URI data connection in the chocotech-models project. This configuration stores the exact OCI registry location of our ModelCar-packaged Llama 3 model and uses specific OpenDataHub annotations so the UI automatically recognizes it in the deployment dropdown menus.

Run the following command in your terminal to create the data connection secret:

cat <<EOF | oc apply -f -
apiVersion: v1
kind: Secret
metadata:
  name: llama-3-8b
  namespace: chocotech-models
  labels:
    opendatahub.io/dashboard: "true"
  annotations:
    opendatahub.io/connection-type-protocol: uri
    opendatahub.io/connection-type-ref: uri-v1
    openshift.io/display-name: "Llama 8b ModelCar (v1.3)"
stringData:
  URI: oci://quay.io/redhat-ai-services/modelcar-catalog:llama-3.1-8b-instruct
type: Opaque
EOF

Exercise 2: Launching the Deployment Wizard

Now that the data connection is staged, let’s deploy the model visually.

  1. Open your OpenShift AI Dashboard and navigate to AI Hub - Models from the left-hand navigation menu.

  2. Select Deployments, then from the project dropdown at the top of the page, ensure that chocotech-models is selected.

  3. Click the Deploy model button to initiate the multi-step model deployment wizard.

Exercise 3: Navigating the Deployment Wizard

Follow the step-by-step instructions below to configure the model runtime, hardware allocation, and MaaS governance properties.

Step 1: Model Details and Location

Instead of manually typing out the OCI registry URL, we will leverage the internal data connection you just created.

  1. For Model location, select the down arrow button then Existing connection.

  2. Select Llama 8b ModelCar (v1.3).: From the dropdown list, or choose the data connection we configured in the previous step (e.g., your pre-defined OCI Modelcar registry or internal storage path containing the model weights).

    1. Folder path: If required by your data connection type, specify the subfolder path containing the weights.

  3. Model Type: Select Generative AI model (Example, LLM)

  4. Click Next.

Step 2: Model Deployment Configuration

  1. Name: Enter llama-3-8b.

  2. Hardware profile: Select gpu-profile.

  3. Deployment resource: Select manual.

  4. Serving runtime: From the dropdown menu, select Distributed inference with llm-d.

  5. Number of replicas: Leave this set to 1. (In a production environment, you would scale this for high availability and usage requirements).

  6. Click Next.

Step 3: Advanced Settings & Governance

This step is critical for integrating the model into ChocoTech’s financial and security framework.

  1. Model Availability: Check the box next to Publish as MaaS.

Checking Publish as MaaS automatically instructs OpenShift AI to generate a MaaSModelRef resource under the hood. This links the newly created model endpoint directly to the MaaS gateway, enabling our Authorino security policies and Kuadrant token quotas to intercept traffic.

  1. Configuration Parameters: Select Add custom runtime arguments. This allows us to fine-tune the vLLM deployment. Add the following parameters:

--dtype=half
--max-model-len=20000
--gpu-memory-utilization=0.95
--enable-auto-tool-choice
--tool-call-parser=llama3_json
--chat-template=/opt/app-root/template/tool_chat_template_llama3.2_json.jinja

  1. Routing Settings: Leave the Rolling update selection and model route timeout selections set to their defaults.

  2. Verify Subscriptions: Ensure the model is mapped to the available tenant subscriptions (such as our Bronze Tier) so your developers can successfully authenticate against it using their assigned API keys.

  3. Review your configuration choices on the summary pane and click Deploy model.

Exercise 4: Verifying the Deployment Status

Once submitted, the platform transitions the model status to Progressing while it pulls the weights and initializes the inference engine.

  1. Navigate back to the Model Serving dashboard.

  2. Under the chocotech-models project view, locate your llama-3-8b model deployment.

  3. Wait until the status indicator shifts from a blue spinning icon to a green checkmark indicating Loaded or Active.

While you wait for the model to provision, it takes aobut 10-15 minutes However once the Deployment is submitted, the Subscriptions and Authorizations we provisioned in module 2 will change from Failed, to Active or Degraded, once they find the model if no one is assigned to the group membership.

You can view in the OPenShift AI dashboard - Setting -Subscriptions and Authorizations.
