3.2: Deploying the governed model via GitOps

This section is under development

With the hardware math verified and the LLMInferenceService architecture selected, it is time to deliver the AI capabilities to ChocoTech’s R&D team.

In a production environment, pulling massive 16GB model weights directly from the public internet every time a pod scales up is highly inefficient and poses a security risk. Instead, ChocoTech uses a "Vault" strategy: downloading the model once to a high-speed S3-compatible storage array inside the cluster, where all inference pods pull their weights locally.

To simplify the deployment for this lab exercise, we will bypass the S3 setup and deploy our model using the Modelcar packaged format. We will pull the model directly from a public Red Hat OCI repository (oci://quay.io/redhat-ai-services/modelcar-catalog:llama-3.1-8b-instruct). While pulling the model upon each restart is not optimal for production, the OCI format offers a clean, streamlined solution for this lab exercise.

1. Extract the Serving Runtime (The Engine)

OpenShift AI includes certified, cluster-wide runtime templates. However, platform engineers often extract these templates into local project namespaces.

Why do we do this? Localizing the serving runtime gives you absolute control over the compute engine. It allows you to inject custom environment variables, lock specific version tags, and apply unique accelerator configurations for ChocoTech’s models without inadvertently impacting workloads in other departments.

Execute the following command to extract the official vLLM template from the central OpenShift AI namespace and install it locally into your chocotech-models project:

oc process vllm-cuda-runtime-template -n redhat-ods-applications | \
oc apply -f - -n chocotech-models

Expected Output: servingruntime.serving.kserve.io/vllm-cuda-runtime created.

Deploy from the RHOAI console simplication step

To simplify the model deployment process through the OpenShift AI dashboard, let’s create a URI data connection in the chocotech-models project. This configuration stores the exact OCI registry location of our ModelCar-packaged Llama 3.1 8B image and uses specific annotations so the UI automatically recognizes it.

Run the following command to create the data connection secret:

cat <<EOF | oc apply -f -
apiVersion: v1
kind: Secret
metadata:
  name: llama-3-8b
  namespace: chocotech-models
  labels:
    opendatahub.io/dashboard: "true"
  annotations:
    opendatahub.io/connection-type-protocol: uri
    opendatahub.io/connection-type-ref: uri-v1
    openshift.io/display-name: "Llama 8b ModelCar (v1.3)"
stringData:
  URI: oci://quay.io/redhat-ai-services/modelcar-catalog:llama-3.1-8b-instruct
type: Opaque
EOF

2. Deploy the LLMInferenceService and MaaSModelRef

Because ChocoTech uses GitOps, we will deploy the model using declarative YAML rather than clicking through the dashboard UI. In OpenShift AI 3.4, a governed deployment requires two distinct resources working together:

  1. LLMInferenceService: This provisions the actual inference engine, requests the GPU, and loads the weights into VRAM.

  2. MaaSModelRef: This is the critical registration resource. It explicitly notifies the MaaS platform that the model exists so it can be exposed through the API Gateway. Publishing as MaaS creates a MaaSModelRef object that registers the model with MaaS for subscription assignment.

Execute the following block to deploy both resources into the chocotech-models namespace:

cat <<EOF | oc apply -f -
apiVersion: serving.kserve.io/v1alpha1
kind: LLMInferenceService
metadata:
  name: llama-3-8b
  namespace: chocotech-models
  labels:
    # These labels force the deployment to appear in the OpenShift AI UI
    opendatahub.io/dashboard: "true"
    opendatahub.io/genai-asset: "true"
  annotations:
    opendatahub.io/model-type: generative
    openshift.io/display-name: "llama-3-8b"
spec:
  # OCI URI extracted directly from the running pod's modelcar container
  model:
    uri: oci://quay.io/redhat-ai-services/modelcar-catalog:llama-3.1-8b-instruct

  servingRuntime: "vllm-cuda-runtime"

  router:
    scheduler:
      template:
        containers:
          - name: main
            args:
              - '--pool-group'
              - 'inference.networking.x-k8s.io'
              - '--pool-name'
              - '{{ .ObjectMeta.Name }}-inference-pool'

  # Tuning extracted from your main container's environment variables
  template:
    spec:
      containers:
        - name: main
          env:
            - name: VLLM_ADDITIONAL_ARGS
              value: "--dtype=half --max-model-len=20000 --gpu-memory-utilization=0.95 --enable-auto-tool-choice --tool-call-parser=llama3_json --chat-template=/opt/app-root/template/tool_chat_template_llama3.2_json.jinja"
          resources:
            requests:
              cpu: '1'
              memory: 12Gi
            limits:
              cpu: '1'
              memory: 12Gi

  # Hardware footprint extracted from the pod specs
  placement:
    accelerator:
      name: "nvidia.com/gpu"
      count: 1
---
apiVersion: maas.opendatahub.io/v1alpha1
kind: MaaSModelRef
metadata:
  name: llama-3-8b
  namespace: chocotech-models
spec:
  modelRef:
    kind: LLMInferenceService
    name: llama-3-8b
EOF

Check the status condition to verify the model is healthy and ready to serve traffic. (Note: This may take several minutes as the node pulls the 16GB OCI image).

oc wait --for=condition=Ready llminferenceservice/llama-3-8b -n chocotech-models --timeout=600s

3. The Post-Deployment Governance Step

A critical architectural concept in OpenShift AI 3.4 is that publishing a model to MaaS (via the MaaSModelRef) does not immediately grant anyone access to it. After publishing, an administrator must create a subscription and add this model to make it accessible to user groups.

However, we pre-wired ChocoTech’s governance strategy in Module 2! You already explicitly listed the llama-3-8b model in your Gold, Silver, and Bronze subscriptions. Because the architecture operates dynamically, the MaaS controllers instantly map the model to your existing subscriptions.
